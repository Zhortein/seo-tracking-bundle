# SEO Tracking Bundle 1.6.0

This additive release turns persisted parent-hit links into privacy-bounded journey reports and adds portable, application-defined business dimensions from collection through typed statistics.

## Journey reports

- `JourneyProviderInterface` reconstructs bounded path fragments from existing `parentHit` links.
- Typed summaries distinguish observed hits, linked hits, fragments, sampled paths, cycles and depth truncation.
- Transition and path rankings have explicit limits between 1 and 100.
- Date and robot filters apply to child hits while an immediate predecessor outside the period can remain as marked boundary context.
- Retention cuts, consent changes and missing browser state start new fragments instead of being presented as new visitors.
- The Doctrine data source is replaceable for custom mappings or high-volume implementations.

These reports identify neither people nor devices. They deliberately expose fragments, not unique visitors or stable sessions.

## Portable custom dimensions

- Applications can pass explicit dimensions through `seo_tracking()`, direct Stimulus values or the tracking endpoint.
- At most 20 sorted entries are accepted, with bounded ASCII keys, scalar values and a 4096-byte normalized JSON limit.
- Invalid, nested, blank, null or non-finite values reject the whole hit before persistence.
- Dimensions are stored on hits and never alter `PageCall` grouping.
- The default and trait-based hit mappings use Doctrine's nullable portable JSON type.
- Custom entities without the optional setter keep their historical collection behavior.

## Dimension statistics

- `StatisticsFilter` accepts exact dimension matches and preserves scalar types.
- `DimensionRanking` and `DimensionRankedValue` expose deterministic per-key rankings.
- The default source hydrates JSON portably rather than using PostgreSQL- or MySQL-specific operators.
- The Bootstrap 5 theme includes an overrideable `dimensions` block.
- Legacy custom hit entities without a dimensions field still produce normal reports; dimension filters match none of those rows.

## Quality and compatibility

- PHPUnit covers bounded journey reconstruction, malformed graphs, filters, dimension validation, persistence, rendering and trait/legacy custom entities.
- Six Node scenarios continue to cover immediate, consent-aware, Turbo and reconnect lifecycles.
- PHPStan runs at its maximum level without a baseline.
- CI covers PHP 8.3–8.5, Symfony 7.3–8.1, Node 22/24, SQLite, PostgreSQL 16 and MySQL 8.4.

## Update

```bash
composer require zhortein/seo-tracking-bundle:^1.6
php bin/console make:migration
php bin/console doctrine:migrations:migrate
php bin/console asset-map:compile
```

Applications using the default hit entity or `PageCallHitTrait` must generate and review a migration that adds the nullable JSON `dimensions` column. Existing rows remain `NULL` and need no backfill. Read the full [upgrade and rollback procedure](https://github.com/Zhortein/seo-tracking-bundle/blob/1.6.0/docs/upgrade-1.6.md).

## Deliberately deferred

Identity-dependent metrics, authenticated or cross-device journeys, cache and pagination for large datasets, pre-aggregation, additional themes and charts, CSV/external analytics adapters and a broader continuously tested database matrix remain in the roadmap.
