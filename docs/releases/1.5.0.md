# SEO Tracking Bundle 1.5.0

This additive release strengthens public collection without changing the tracking schema: optional endpoint rate limiting, explainable bot classification and privacy-safe observability for rejected requests.

## Endpoint protection

- Hit creation and closure can use independent named Symfony RateLimiter policies.
- The integration is disabled by default and Symfony RateLimiter remains an optional runtime component.
- The default bucket key hashes Symfony's resolved client IP; applications can replace the key resolver or complete policy.
- Rejected requests return HTTP 429 before consent checks, JSON parsing or database access.
- Standard limit and retry headers are returned when the configured limiter supplies them.

## Explainable bot classification

- `BotClassification` carries a boolean plus optional classifier, category and rule identifiers.
- The conservative default distinguishes common search crawlers, social previews, uptime monitoring and generic crawlers.
- Applications can replace `BotClassifierInterface`.
- Existing `BotDetectorInterface` replacements continue through a compatibility adapter.
- Only the existing bot boolean is persisted. The explanatory result is available on `PageCallTrackedEvent` and does not become visitor identity.

## Invalid-request observability

- Rejected requests use a separate no-op-by-default reporter and never become SEO hits.
- Stable reasons cover malformed JSON, unsupported roots, invalid fields, consent denial, rate limiting and unknown hit closures.
- Events expose a closed set of bounded method, route and content metadata.
- Raw payloads, URLs, IP addresses, referrers and User-Agents are never passed to the reporter.
- Reporter failures are suppressed after the rejection decision, preserving the original public response and zero-write behavior.

## Quality and compatibility

- PHPUnit covers Symfony limiter wiring, custom and legacy bot classifiers, every rejection reason, safe metadata and reporter failure.
- Six Node scenarios continue to cover immediate, consent-aware, Turbo and reconnect lifecycles.
- PHPStan runs at its maximum level without a baseline.
- CI covers PHP 8.3–8.5, Symfony 7.3–8.1, Node 22/24, SQLite, PostgreSQL 16 and MySQL 8.4.

## Update

```bash
composer require zhortein/seo-tracking-bundle:^1.5
php bin/console asset-map:compile
```

There is no Doctrine schema migration from 1.4. All new persistence-adjacent integrations are disabled or no-op by default. Read the full [upgrade and rollback procedure](https://github.com/Zhortein/seo-tracking-bundle/blob/1.5.0/docs/upgrade-1.5.md).

## Deliberately deferred

Visitor-flow reports, application-defined dimensions, high-volume cache/pre-aggregation, additional themes and charts, CSV/external analytics adapters, identity-dependent metrics and a broader continuously tested database matrix remain in the roadmap.
